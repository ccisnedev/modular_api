# Migrating from 0.7.x to 0.8.0

What changes for consumers moving to 0.8.0 (issue #47). The three SDKs share the
version; only the TypeScript SDK has a breaking change.

## 1. TypeScript: strict routing (breaking)

Up to 0.7.x the Express routers were case-insensitive and non-strict, so these
variants of `/api/payments/execute` still reached the use case:

| Request path | 0.7.x | 0.8.0 |
|---|---|---|
| `/api/payments/execute/` | use case | `404 {"error":"Not found"}` |
| `/api/payments//execute` | use case | `404 {"error":"Not found"}` |
| `/API/Payments/Execute` | use case | 404 |

A middleware that compared `req.path` exactly did not recognize those variants,
so an auth check written that way could be bypassed.

**Action:**

1. Make clients call the exact path shown in `{basePath}/openapi.json`: same
   case, no trailing slash, no repeated slashes.
2. If some clients cannot be fixed in time, set
   `new ModularApi({ strictRouting: false })`. It restores the 0.7.x routing and
   logs a deprecation warning at startup; it will be removed in a future minor.
   Even with it, `resolvedRoute(res)` matches only the canonical path.

Python and Dart already routed strictly; nothing changes for their clients.

## 2. All SDKs: the resolved use case is available to middlewares (additive)

Before any plugin or custom middleware runs, the framework attaches the use case
the request will run: `{ module, useCase, method, path }`, or nothing on a 404, a
405 or an endpoint that is not a use case.

| SDK | API |
|---|---|
| TypeScript | `resolvedRoute(res)` |
| Python | `resolved_route(request)` |
| Dart | `resolvedRoute(request)` |

**Action (recommended):** rewrite auth and authorization middlewares that compare
the raw path. Deny by default and decide by the resolved route, as shown in
[Protecting use cases](../guides/protecting-use-cases.md).

## 3. TypeScript: requests that are rejected for their path are now measured

The 404s for non-canonical paths go through logging, tracing and metrics like any
other 404, under `route="UNMATCHED"`. Expect those series to appear if clients send
such paths.

## 4. Dependent packages

`modular_api_sqlserver` (Dart) declares `modular_api: ^0.7.0`, which excludes
0.8.0. Until it is released with a widened constraint, an application that wants
core 0.8.0 alongside it needs a `dependency_overrides` entry.
